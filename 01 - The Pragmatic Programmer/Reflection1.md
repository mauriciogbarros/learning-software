1. Pay attention to details but be aware of the big picture, and always stay informed.
2. Time is my greatest asset. Use it wisely, produce good code and invest in myself.
3. Don't accept to live in a building with broken windows, be a catalyst for change while knowing what "good enough" is.
4. Knowledge is a very important asset but it expires. This means that constant investment in my knowledge portfolio is required. And it's not just what I've got, it also how I package it.
5. For code, a good design is able to adapt to change, this requires not repeating blocks of code and to always aim for orthogonality (decoupling). This also means that things need to reversible.
6. Use tracer bullets to know if you are hitting the target, use prototypes to answer specific questions, and learn how to estimate time and money to achieve something.
7. Program close to the problem domain.
8.  Plain text is the best format to store knowledge, since it is a technology that will never expire.
9.  The command shell is my workbench and the editor are my tools to shape code, make them my own and be fluent.
10. Code is in constant change, so always use version control. And when problems arise, fix the problem, not the blame. A lot of times, going through dense logs is required to debug a problem, text manipulation is a must.
