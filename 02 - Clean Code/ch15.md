# 15. Clean Tests
- Clean tests are readable, fast, isolated, repeatable, self-verifying, timely and designed.
  - Readability is perhaps even more important in unit tests that it is in production code.
  - In as test, you want to say a lot with as few expressions as reosanable.
- The Arrange/Act/Assert pattern (AAA)
  - The first part (Arrange) builds up the test data.
  - The second part (Act) operates on that test data.
  - The third part (Assert) checks that the operation yielded the expected results.

---

## Domain-Specific Testing Language
- Rather than using the APIs to manipulate the system, we build up a set of functions and utilities that make use of those APIs and that make the tests more convenient to write and easier to read.
  - These functions and utilities become a specialized API used by the tests.

### Composed Assertions
- Functions created within the testing suite are called *composed assertions*.

### Composed Test Results
- These are used when the test results are needlessly complex and can be compressed down into a smaller form that is easy to understand.

### Dual Standard
- There are things that you might never do in a production environment that are perfectly fine in a test environment.
  - They never involve the issues of cleanliness.

### The Single Assert Rule
- A good test asserts one and only one thing.
  - A test can have many assertion statements and still assert one logical fact.

### The Single Act Rule
- The rule above should be called the Single Act Rule since each test is testing one and only one action.

---

## F.I.R.S.T
- The desired characteristics of tests
  - **Fast**
  - **Isolated**: Single Act Rule
  - **Repeatable**: in any environment
  - **Self-validating**: boolean output, either pass or fail.
  - **Timely**: unit tests should be written along with the production code

---

## Test Design
- Tests need to be designed to reduce their coupling to the production code.
  - Changes to the requirements affect as few tests as possible.
- The principles and reules of software design apply to the tests as much as they apply to the production code.
  - Coupling must be minimized.

---

## Conclusion
- Tests are as important to the health of a project as the production code is.
- If you let your tests rot, then your code will rot too.
