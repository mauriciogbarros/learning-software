## Programming by Prompt

- This is a very new technology, and we don't have a good handle on how to use it yet.
- With each new change to the prompt, AI regenerates the program from scratch as opposed to modifying the existing program.
  - With all the ambiuities in the prompt, how can I be sure that the regenerated program doesn't break something that worked in the previous one?

### Infancy

- In order to effectively program large systems by prompt, we are going to need AI tools that allow for incremental changes.
  - We are also going to need ways to eliminate ambiguities in our prompts.
- In short, we are going to need a formalism - a prompt language that is unambiguous and precise and that cannot be misinterpreted by the statistical fuzzy nature of LLM algorithm.
- We'll alos need to come up with a way to mean what we say.
  - Even if we have a perfectly precise language, it is easy to precisely say something that is wrong.
  - To ensure that our precise statements are accurate descriptions of our intent, we should state our intent in at least two different ways. (Overloading)

### A SWAG (Scientific Wild-Ass Guess)

- Debugging the code is relatively simple; but can you debug the prompt?
  - Even if you can "fix" the prompt, are you sure it will generate code and tests that pass if you apply the prompt more than once?
- Programming is formal, and humans require overloading.

---

## Conclusion

- Programmers will become the lawyers of AI, responsible to reason through and draw up the precise and accurate formal requirements and contracts for the applications our clients need.
