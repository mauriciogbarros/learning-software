# 11. Be Polite
- We want our modules to be polite.
  - As you read the code, you find it to be "pretty much what you expected."
- A module is a bounded set of functios and variables.
  - This might be composed of one class, several classes, or no classes at all. What matters are the functions and variables.
  - A module may also be contained in a single source file or several source files. What matters is the cohesion of the functions and variables, and not the artificial boundaries that separate them.
  - Another common word for a module is *component*.
- The public functions, possibly organized into public classes, represent the interface of your module.
- The private functions, also possibly organized into prive classes, represent the implementation of your module.
- That module has a narrow interface and deep implementation - and that's a good thing.
- The Stepdown Rule: each descending call goes **one level** of abstraction down.
  - Not two, not three. Just one.

---

## The newspaper metaphor
- At the top, you expect a headline what will tell you what the story is about and allow you to decide whether it is something you want to read.
- The first paragraph gives you a synopsis of the whole story, hiding all the details while giving you the broad-brush concepts.
- As you continue downward, the details increase until you have all the dates, names, quotes, claims, and other minutiae.
- Most of us never read the entirety of an article.

```csharp
while (interested) readMore;
```

- The classes and functions within a module should all be related to a single topic - a single responsibility - with a nice structure that proceeds from high-level policy to low-level detail.

### Be polite
- When you write functions that encapsulate a single level of abstraction, it allows your readers to escape early.

---

## The stepdown rule: once again
- Descend one level of abstraction at a time.
  - Each function has a name that defines what the function does, and each function consists of a set of lines that describe the implementation and that are all at the same level of abstraction.
  - Each of those lines, if it is not already at the lowest level, calls functions at the next level down.
- This is a polite practice, and it helps avoid the abstraction roller coaster.

---

## The abstraction roller coaster
- Going up and down through levels of abstraction.
- Riding that roller coaster is  not fun for the reader.

---

## This is how we write, but not how we want to read
- We write code on the roller coaster.
- First, make it work. Then, make it right.
- You are not done when the code works. You are done when the code reads well.
