# 10. One Thing
- Bjarne Stroustrup: "Clean code does one thing well."
  - What does *one thing* mean?

---

## Extract Method Refactoring
- A function does one thing if you cannot meaningfully extract another function from it.
- What does *meaningfully* mean?

```java
public void addRental(Rental rental) {
	rentals.addElement(rental);
}
```

- It is not meaningful to extract the body of that function into a new function:

```java
public void addRental(Rental rental) {
	doTheAdd(rental);
}

public void doTheAdd(Rental rental) {
	rentals.addElement(rental);
}
```

- In general, following this recommendation will cause you to create a lot of small functions.
- What will you be extracting?
  - Often the bodies of `if`/`else` statements and `for`/`while` loops.
  - The predicates out of those statements so that those statements will be composed of little more than the keywords and the function calls.

```java
if (shouldDeleteRecord(r))
	deleteRecord(r);
```

### This shouldn't be controversial
#### 1. Drowning

#### 2. Small functions don't obscure intent
- A well-designed and well-named structure of namespaces, classes, and functions reveals intent.

#### 3. Performance
- If you are writing a first-person shooter game, or a high-speed trading app, or the guidance system for a hypersonic missile, then nanoseconds can be pretty important.
- Good compilers will often do the inlining for you, without your knowledge.

#### 4. Bouncing around
- Organize extracted functions in the order that they are called.

#### 5. Entanglement
- When you extract one function from another, you may be entangling the logic of those two functions.
- If there are several different facts established by the higher-level function that you must keep in mind while reading the lower-level function - then there is a reasonable chance that the extraction might not be worth doing.

## What are large functions anyway?
- Every large function is really hiding a class (or more) inside it.
- Every large function has a set of local variables and a set of indented regions that manipulate those variables.
  - Those variables should really be fields of a class, and those indented regions should be methods of that class.

### Extractions and classes
- Sometimes when we extract functions, it is convenient and clean to allow those functions to communicate through variables in the scope (the class) that contains them.
